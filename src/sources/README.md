# Publisher subscriptions

Feed and website connectors persist ordinary sources/source_items/item_revisions and reuse the shared transactional collection store. Telegram imports the shared store and link helpers directly. All article crawls are serial and use the existing private Crawl4AI adapter. Article reads apply Readability to rendered HTML without script execution or resource loading, then produce GFM Markdown. Index reads retain page-wide Markdown for discovery. CommonMark/GFM AST parsing preserves UTF-16 link spans, nested images, reference links and repeated anchors. Every actual destination in the selected article remains stored; assets, same-page navigation and ancillary credit/social/comment sections are not automatic evidence. No URL-domain blacklist is used. No model or publishing calls occur here.

Use the exports in `index.ts` to list/add/edit/seed subscriptions. API results use `PrimarySourceView`, a configState-discriminated valid/invalid union. Invalid legacy rows expose only safe identity fields and can be disabled with `{enabled:false}`. Edits load just the requested row. Once items have been ingested, URL/kind changes require adding a replacement source. A server-owned metadata marker keeps identity locked after retention cleanup; operators cannot set or clear it. Inputs are strictly validated and DNS checked; HTTP(S), no credentials, public addresses only. Article links default to the configured hostname. Feed-only `articleLinkPolicy: 'external'` opts one subscription into external public HTTP(S) articles, including canonical redirects. Slash-terminated path prefixes still apply to all article URLs. Websites cannot opt in; feed index redirects must still match the configured hostname. Fetch-time DNS and private-network checks are unchanged. Operators choose sources; a publisher label is not a claim authority rating. There is no automatic primary evidence role.

Hacker News at `https://hnrss.org/newest` needs an explicit external-link opt-in. PATCH only that subscription with `{ articleLinkPolicy: 'external', articlePathPrefixes: ['/'], feedDateRole: 'submission' }`. HN RSS pubDate is a submission timestamp, not publisher publication. With `feedDateRole: 'submission'`, it is stored as `metadata.submittedAt` and `metadata.feedEntryPublishedAt`; it never becomes `published_at`. Actual article dates must pass the collection window. Fresh submissions linking old dated articles are intentionally excluded. Undated articles require `unknownPublication: 'collect_once'` and retain `published_at=null`. This is collection, not an editorial claim that an old article is new. The default `feedDateRole` is `publication` for ordinary publisher feeds. Changing this option affects later reads and unprocessed discoveries; it does not rewrite existing revisions or retroactively correct older proxy timestamps. Websites cannot use submission dates. Revert external access with `{ articleLinkPolicy: 'same_host' }`; saved backlog URLs are revalidated against the current policy before reads.

`maxArticles` accepts 1 to 50 attempts per source per cutoff, default 3. `backlogLimit` optionally accepts 1 to 1000 discoveries, default 200. `retryDelayMinutes` optionally accepts 1 to 720 minutes, default 60. These source-specific options can be set through `PATCH /api/primary-sources/:id`; unrelated edits preserve them. Crawls remain serial. A caller's smaller entry limit still wins, including zero. Raising budgets is an operator decision, not a seed or migration change. The source editor exposes the same ranges and optional settings. Blank optional fields leave existing settings unchanged; enter the documented defaults explicitly to restore them. Its Hacker News preset opens a new unsaved draft with 20 attempts, a 200-entry backlog, 60-minute retry base, external links, submission dates and undated collect-once. It never edits an existing subscription or schedule automatically.

Scheduled collection enters through pipeline/collection.ts using the existing collectionCron. Publisher collection runs before Telegram so a Telegram session failure does not prevent publisher ingestion. Each source has independent batch_sources state. Discoveries and article-attempt reservations commit before network reads; items and successful progress commit together. Publisher partial checkpoints also update sources.collection_cursor so a failed or abandoned batch does not erase discovery or retry state. Ordinary Telegram cursor behavior is unchanged. A stale batch cannot replace a newer publisher source cutoff. Source edits and checkpoints lock the source before its batch rows. Each edit increments a database configuration version; checkpoints taken before that edit fail with `primary_store_config_changed` instead of overwriting recovered policy state. Apply `migrations/160_source_collection_config_version.sql` before running the new collector. It adds one version column, without changing source options, cursors or item history. A later failure cannot remove saved items. Failed sources are resumable, but failed attempts also consume that cutoff's budget. Telegram discovery and snapshot guards affect Telegram only.

Scans use the fixed batch cutoff and configured window of at most 48 hours. Seeds use two articles per publisher, at most five sources. GUID or normalized article URL identifies an item; body/link edits create revisions, unchanged content is not replayed. Revisions/cursors/batch membership share transactions. Retention is never extended on refetch.

The JSON cursor holds a durable, bounded backlog. Eligible discoveries survive removal from the next feed snapshot. Dated entries expire outside the current collection window; undated entries expire one window after discovery. On overflow, unattempted entries take priority over retries, edit checks and skipped undated pages. Within each group the freshest entries survive. `cursor.backlogOverflow` counts dropped admission events, including rediscovery of an overflowed entry. Overflow and expiry can lose coverage; no finite backlog can cover an arbitrarily fast feed. Items that rotate out between polls were never discovered and cannot be recovered by this collector. Backlog data uses existing JSON cursor columns. The configuration fence requires the source-specific version-column migration noted above.

Within the retained backlog, oldest untouched discoveries run before retries. Undated entries use their discovery time for scheduling only, never as publication. Retries use exponential delays capped at 12 hours and record only safe error codes. A crash after a reservation consumes the attempt and delays its retry, rather than allowing unbounded repeat reads. Fresh arrivals cannot be blocked by repeatedly inaccessible oldest articles. After untouched work, due retries precede least-recently-checked known articles. Every third batch with a continuing fresh backlog reserves one edit check within the budget. A failed edit attempt also consumes that reservation so it cannot pin the edit cadence. Continuous input above capacity can delay retries; increase the explicit budget or accept bounded loss. Sources with deferred failed articles stay failed with `primary_article_retry_deferred`; the cursor retains the original article error. An attempted ID is not read again at the same cutoff. Retry admission requires a later cutoff after the saved delay, so orchestration must permit new scheduled batches rather than repeatedly parking the same snapshot. An index outage still reports failure, but already discovered articles can drain within the same budget. OpenAI HTTP 403 remains an upstream access failure. This collector does not disable access checks or bypass challenges.

RSS/Atom XML is bounded to1MB/1000 entries, rejects DTD/entity declarations and malformed XML, disables entity processing and validates parsed fields. Publication comes from RSS pubDate/Atom published, never updated. Website index dates must belong to a linked publisher card; article metadata or narrowly scoped publication front matter are used when available. Date-only timestamps normalize to UTC day start rather than the server timezone.

Unknown publication defaults to skip. Skipped IDs and successfully collected undated IDs are now tracked separately. Changing `skip` to `collect_once` through the source API recovers skipped IDs in the source and unfinished batch cursors, including legacy mixed-ID cursors. Retained already-ingested undated items are not replayed, and attempt budgets are not reset. Recoverable saved URLs remain subject to backlog expiry; legacy cursors had no URLs, so legacy entries must still appear in a later index. Direct SQL metadata edits bypass this legacy recovery.

Optional `collect_once` follows an undated article once and persists `published_at=null` with `publicationKnown=false` and `unknown_collect_once` metadata. `collected_at` and `retention_at` are lifecycle timestamps, not publication dates. A date found after article fetch must still pass the cutoff/window check. Undated completion memory is bounded to 1000 IDs, so very old IDs outside that memory can eventually be rediscovered.

Five seed endpoints were publicly verified on2026-10-01. OpenAI/Anthropic website indexes and NVIDIA/Hugging Face articles rendered successfully through the actual crawler. Google AI RSS returned200 but had no entries in the48h probe window and correctly collected nothing. Seeds are idempotent and do not override manually disabled subscriptions. Root owns invoking seed API and HTTP/UI route registration; no automatic startup writes.

For retained-item repairs, `refreshPublisherItem(itemId,batchId)` requires the caller's pipeline lease and a parked failed/waiting batch. It uses the original public article URL and shared revision store, preserves publication/retention/cursors/completed-source state, and enrolls changed content in that same batch. Operator lookup SQL and exact lease-held invocation are in `tmp/primary-publisher-refresh-api.md`. No automatic repair or startup writes.

Proof and handoff: tmp/primary-sources-api.md and tmp/primary-sources-report.md. Unit regression tests and disposable database tests cover partial progress, nullable timestamps, revisions, cursor completion, source failures and Telegram coexistence.

## Portable source links

Reddit post and comment permalinks drop temporary challenge parameters such as `solution`, `js_challenge`, `jsc_token` and `jsc_orig_r`, plus known share/tracking parameters. Collection preserves the original text and link offsets while storing the clean destination. Research normalizes both incoming URLs and crawler redirect citations, so a browser challenge does not become a public source link. Publication cleans and deduplicates older stored variants too. Meaningful query parameters, comment paths and unrelated websites remain unchanged. This does not bypass challenges or change access assessments.

## Media discovery

Collected items and revisions store `metadata.media` as an array of `{type:'image'|'video',url:string}`. Discovery reads selected article images, lazy images, picture/srcset sources, native video sources, Markdown images/references and direct video links. Feed entries also retain typed RSS/Atom enclosures, Media RSS content/thumbnails and embedded content images/videos. Feed media survives rotating indexes through the existing JSON backlog. Publisher collection and operator refresh merge adapter metadata with content discoveries. Media-only changes create revisions.

URLs resolve against the article URL and pass the existing public HTTP(S) URL policy. CDN hosts are allowed. Discovery removes duplicates and keeps at most 100 descriptors per item. It does not download media, execute scripts, inspect video players, or persist files. Navigation, author avatars, logos, tracking pixels, video posters and unrelated social posts are not content media. Branding checks apply to Markdown alt text, references, lazy image destinations and feed attachments as well as HTML attributes. Article cleaning removes author-card portraits before conversion loses their container context. Publication preparation repeats URL checks for previously stored descriptors. Opaque category banners and unrelated roundup images require the publication-stage visual relevance check against the specific story. Blob/data URLs and iframe-only players have no retrievable descriptor; no guessed URL or site-wide Open Graph preview is substituted.

Each publisher backlog entry stops after `requestMaxAttempts` consecutive failed reads, default three, across collection cutoffs. Rediscovering the same retained entry does not reset its failures. Retry delays still use the source-specific exponential backoff. Successful reads reset the failure count for later edit checks. Exhausted entries remain in the bounded backlog until normal collection-window expiry.
